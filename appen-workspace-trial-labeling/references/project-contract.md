# 项目合同与来源优先级

## 何时读取

当任务涉及规则学习、live 刷新、口径冲突、AI 参与范围、任务顺序或证据优先级时，读本文件。

## 来源优先级

发生冲突时，按以下顺序判断：

1. 用户当前明确指令和当前外部操作授权；
2. 项目方针对本项目/本批次的后发专项确认；
3. 当前任务页面、当前 `annotate.html` 校验器和当前任务包；
4. 最新正式书面 SOP 和管理员正式通知；
5. 工作区 `AGENTS.md` 和当前项目合同；
6. 本 Skill 的跨任务默认规则；
7. 旧会议、旧群消息、AI 纪要和历史习惯。

普通成员的理解、经验或猜测只是线索，不单独成为项目规则。线下专项确认由用户转述时，在工作区合同中记录时间、范围和被覆盖的旧规则。

## AI 参与范围

当前 Appen Workspace 项目已由用户转述项目方线下确认：允许并建议 AI 参与全流程。这一专项口径覆盖旧 SOP 中“AI 不得处理整个流程”的限制。

该授权允许 Codex：

- 顺序阅读和筛选工作区文件；
- 完成任务要求的本地产物；
- 建立任务轨迹和阅读耗时记录；
- 审核 Rubric，完成题目级评分与判定；
- 生成和验证 draft/shared HTML。

该授权不自动包含飞书写回、文件上传或最终提交。外部动作按当前用户授权独立判断。

## 稳定流程合同

- 先做题，再审题。先独立产出期望输出物，再从源文件独立审核Rubric，实际产物用于交叉检查。
- 顺序为：任务执行与轨迹 -> Rubric 逐条审核 -> 题目级评分 -> 题目级判定 -> draft -> shared。
- 分配或领取任务后，必须再次核对分配行/领取记录、Task ID、岗位、案例说明、压缩包和 HTML 内部 ID；不按题号、文件名相似度或个人印象猜测任务身份。
- 文件选择本身是考察点。同名目录、多版本、错扩展名、模板残留和不相关文件必须显式核对。
- 明确的陷阱值、干扰值按题面、版本、时间和业务口径核验后排除，并向参与计算的AI传入排除条件；仅有异常值或与Rubric预期不符时继续核查，保留尚未解决的源文件冲突及其影响。
- 当前 Workspace 项目把工作区既有文件视为只读证据。复制到单题 `work/` 后仍不得修改、删除、重命名、移动或覆盖任何已有代码、配置、日志、数据或业务文档；只允许新增题面明确要求且源工作区中原本不存在的期望输出物。
- 当前任务原始 `annotate.html` 的内联脚本同样属于只读证据。填写、恢复和导出优先通过 Chrome DevTools MCP 集成操作真实页面；不可用时使用 `scripts/cdp/` 的可信 Input 事件，必须操作原生应用时使用 Computer Use。只能通过页面可见控件改变常规表单状态，并使用原生“暂存”“任务完成”按钮导出；不得用 Playwright、控制台、`evaluate_script`、`Runtime.evaluate`、DOM 注入或本地代码直接写状态，也不得修改计时、校验、导出、暂存、完成、只读模式或事件监听代码。工作区 `AGENTS.md` 明确记载的既有轨迹 ID 专项技术校正只适用于其限定条件，不能扩展到其他状态或源 HTML。交付前按 [annotation-form-contract.md](annotation-form-contract.md) 和 [delivery-and-submit-boundary.md](delivery-and-submit-boundary.md) 执行只读完整性检查。
- 题面若要求修改既有文件，或指定输出路径已经存在，属于实质合同冲突。停止执行和交付，保留题面、源文件和 live 红线证据，等待项目方确认；不得通过工作副本绕过红线。
- 实际使用文件、页面勾选文件和任务轨迹提及文件应相互覆盖；所有勾选文件都要有真实正数耗时。
- 所有数字、事实和方向性概括都要回到源文件；不以 Rubric 自身的预期值作为正确性证据。
- 单条Rubric独立评分；本条内部矛盾、跨Rubric冲突和源文件冲突分别处理。无自身缺陷的条目正常给5分，跨条冲突具体备注并影响题目质量与总体判定；详见[annotation-form-contract.md](annotation-form-contract.md)。
- 真实问题与修改建议写清具体对象、依据、影响和改法。无问题字段按当前页面约定填写，强制非空时允许重复使用页面认可的最短无内容说明，核验依据保存在单题证据中。
- 目录树、轨迹、Rubric、题目级判定和总体理由中的同一事实必须一致；发现互斥结论时重新核验源文件。
- 不伪造阅读、耗时、证据、页面状态或成功回执。

## 输出合同优先级

当文件名、格式、相对路径或内容范围不一致时，优先采用当前任务 Prompt/任务原文中的明确输出要求，其次采用任务包内针对输出文档的专项要求，最后才使用页面或模板中的泛化“期望输出”。下位来源不能覆盖上位来源；实质冲突会改变交付物时，保留冲突证据并刷新 live 规则或请求确认。

只把题面要求的交付文件放入结果目录。中间文件、调试输出、证据、扫描结果和本地辅助脚本留在单题工作副本的证据/临时目录。

## Live 来源处理

工作区 `AGENTS.md` 记录当前项目的群名、文档/表格 URL、minute token、当前身份和最近核实时间。

- 群消息使用 `lark-im`。
- 在线表格使用 `lark-sheets`。
- 妙记Transcript使用`lark-meeting`。
- 每条 token/chat_id 的下游命令都显式沿用 `--as user`，不依赖 `auto`。

AI 纪要或摘要只作线索。项目方明确说纪要不准时，以原录屏、完整 Transcript、书面 SOP、当前 HTML 和源文件交叉核对。

## 材料归属

- Skill：跨任务稳定流程、表单合同和交付边界。
- `AGENTS.md`：live 入口、项目特定确认、默认工具、当前材料路由和授权边界。
- 单题目录：原包、工作副本、Prompt、Rubric、证据、轨迹、产物、页面状态和回执。

易变群规不得整篇复制进 Skill。只有已经多次任务证明、会改变执行决策且可测的规则才进入 Skill。
