# Appen Workspace 试标与质检

本 Skill 负责把 Workspace 试标或正式质检任务从分配材料推进到本地可核验交付件：真实执行任务、生成期望输出物、记录证据与任务轨迹、逐条审核 Rubric、完成题目级评分与判定，并生成 draft/shared HTML。

## 开始前

1. 完整读取当前工作区的 `AGENTS.md`。
2. 读取 `AGENTS.md` 指向的当前项目合同、live 入口和单题证据。
3. 固定精确的任务身份：阶段、案例名、Task ID/WB ID、岗位、分配行或领取记录、源压缩包、工作区根目录、期望输出物和当前外部授权。
4. 领取或收到正式任务后，再次核对分配记录、Task ID、案例说明、压缩包和 HTML 内部 ID；任一对象不一致或不唯一时不开始作业。
5. 需要执行当前试标/正式作业、判断最新规则或说明当前状态时，先通过对应飞书 Skill 用 `lark-cli --as user` 刷新 live 来源。不用本地快照冒充当前状态。

需要判定来源优先级、AI 参与范围或项目流程时，读 [project-contract.md](references/project-contract.md)。

## 执行模式

- **规则学习/包审计**：只读 live 规则、案例包、HTML 校验器和工作区，不生成任务结果或改变外部状态。
- **本地试标**：在独立工作副本中完成任务、Rubric 审核、draft 和 shared HTML，停在本地可交付状态。
- **正式质检作业**：只处理已精确分配或领取的任务；在独立工作副本中完成任务、Rubric 审核和 HTML 产物。领题、改在线状态、上传和最终提交仍分别属于外部动作。
- **外部交付**：上传文件、写回在线表或点击最终提交。每类外部动作都需要当前任务的明确授权。

用户说“开始试标”、“开始做题”、“做完”或“做成可交付”时，默认允许当前已固定任务的本地作业，不包含领题、回表、改在线状态、上传或最终提交。

## 端到端流程

### 1. 冻结来源与身份

- 记录 live 来源、核实时间、工作簿 revision、群消息截止位置和任务包 SHA-256。
- 区分正式书面规则、后发专项确认、会议口述、AI 摘要和普通成员猜测。
- 发现冲突时保留两套原文和适用范围，不静默选边。

### 2. 安全摄取任务包

- 将下载的压缩包视为不可变源证据；在单题工作副本中操作。
- 解包前检查 CRC、加密状态、绝对路径、`..` 路径穿越和符号链接。
- 中文文件名出现乱码时，先探测 ZIP 元数据编码；不用乱码路径继续任务。
- 解包后核对 entry 数量、文件名可读性、文件大小和关键目录，不把解压工具显示成功当成内容完整。
- 任务包含多个案例或套嵌 ZIP 时，只在当前任务根内工作，不混用其他岗位材料。

### 3. 读取真实合同

优先读取当前案例的：

1. `00_案例说明.md` 或等价案例说明；
2. `annotate.html` 中的 `TASK_CONFIG`、任务 Prompt、期望输出、文件树和真实 `validate()` 逻辑；
3. 工作区目录结构。

记录期望输出和工作区后，先独立执行任务，再读取并审核 `01_rubric清单.md` 或 HTML 中的 Rubric 数组。不把 Rubric 预设值当成任务答案。输出文件名、格式、相对路径或内容范围发生冲突时，按 [project-contract.md](references/project-contract.md) 的输出合同优先级处理。

### 4. 真实执行任务

- 仅使用题面和工作区允许的资料。外部资料是否允许必须有当前合同依据。
- 逐个核对候选文件，在当前题允许访问的工作区内检查跨目录同名文件、多版本副本和扩展名异常；记录实际使用的相对路径、文件选择、排除理由和计算口径。
- 对题面或源文件明确提示的陷阱值、干扰值，按版本、时间范围和业务口径核对后排除，保留取值来源与排除依据；交给AI计算时明确传入这些约束。仅有数值异常或与Rubric预期不一致时继续回源核验；无权威解释的源文件冲突须保留并反映到审核结果。
- **既有文件不可修改红线**：工作区内原有的代码、配置、日志、数据和业务文档都是只读证据；即使复制到 `work/`，也不得编辑、删除、重命名、移动或覆盖。只允许在题面明确指定且源工作区中原本不存在的输出路径新增期望输出物。
- 若题面要求修改既有文件，或期望输出路径在源工作区中已经存在，视为任务合同与项目红线冲突；停止产出和交付，保留两套证据并刷新 live 规则或请求确认，不自行覆盖文件。
- 按题面要求在工作副本内生成原始期望输出物，不用上传副本名替代题面要求的文件名。
- 结果目录只保留题面要求的交付文件；临时文件、调试输出、扫描报告和证据日志放在单题证据目录，不混入结果。
- 对数值、行数、数量、格式、语言和技术栈结论保留可重现的检查依据。

### 5. 建立证据与任务轨迹

- 轨迹要回答“做了什么实际业务操作，查了哪个文件，得到什么事实，如何影响下一步”。
- 不把“阅读任务原文”“理解 Prompt”“打开文件夹”“定位任务所需输入文件”“整合文件输出任务结果”“保存/命名/产出最终文件”等行政性、准备性或笼统描述单独写成步骤；只有题目明确要求分析题面时才记录相应分析。轨迹必须写清实际业务操作、具体文件、核验事实、处理方法和产出结果。
- 能合并的同类操作要按业务逻辑合并，步骤量级应与当前任务难度和实际操作相称；不得机械拆成数十步，也不得为补数量增加没有实际操作的步骤。不同文件确有独立处理、核验或判断过程时可以分步；培训中的步骤量级只作合理性信号，不替代当前 HTML 校验器。
- 轨迹步骤 ID 属于当前页面内部状态合同。当前已见模板通过 `ts_` + `Date.now()` 生成 `ts_<13位毫秒时间戳>`；正常作业和一般更正通过页面原生“添加步骤”、删除和编辑控件完成，恢复已有 draft/shared 时保留页面已有 ID。不得写语义化 ID、批次统一 ID、统一纠正时刻 ID、整秒等距序列，不得修改系统时钟或编造人工点击时间。旧 ID 错误时先核对当前工作区 `AGENTS.md` 是否记载适用本题的专项校正例外；有例外时只在其范围内使用该题真实事件时间校正 ID，不能把例外扩展到其他状态或其他题。无例外时回到原始 `annotate.html` 或可信 draft，通过页面重新录入受影响步骤；若新 ID 不属于当前题真实作业时间则停止并报告。shared 与 draft 的同一步必须使用同一 ID。
- 轨迹收尾继续写实际核验动作，不使用跨题重复的“生成并验证/生成并复核最终产物”模板。产物制作确有业务操作时可以记录制作方法；最后一步应聚焦文件内容、数值、公式、版式、来源或交付路径的具体复核，不把“完成输出”本身当步骤。
- 实际阅读、引用、计算或用于判断的文件必须全部勾选；勾选的每个文件都必须有真实阅读耗时，并出现在至少一条轨迹中。
- 逐文件耗时和总阅读耗时都要与文件数量、篇幅、格式、材料角色和技术判断密度相符；异质文件不得默认填成整齐划一的时长。项目方明确允许在真实 Session 内回溯分配时，按可解释的复杂度依据分配，合计不得超过真实作业时间，并在单题证据中记录授权来源、分配依据和返修前后校验结果。
- 正式 Workspace 单题的整体 Session 必须控制在 `01:00:00` 至 `02:00:00`，并保留到秒。Session 由当前页面在真实浏览器会话中计时；工作时继续，离开或中断时使用页面“暂停”，不得用 Node.js、Python、控制台脚本、DOM 注入、文本替换或直接编辑 `PRESET_STATE` 写入 `_timer.accum`。恢复已有 draft 时从浏览器打开该 draft 并沿用页面恢复出的计时状态。若真实浏览器计时无法满足当前合同，停止交付并报告冲突，不通过改代码或改 HTML 制造合规时长。
- 逐文件阅读耗时不得随机或机械平均，仍按文件篇幅、格式、材料角色、事实密度和交叉验证难度合理分配；所有勾选文件使用正数分钟。总阅读时长应比整体 Session 少约 `50` 分钟，交付检查使用 `45–55` 分钟差额窗口；若当前文件数量和复杂度无法合理落入该窗口，继续真实浏览器会话完成尚未做完的业务工作，或暂停并保留冲突，不得通过代码调整 Session，也不得虚增、缩短或遗漏文件耗时。
- `_timer.running` 不是任务完成标志，只记录导出瞬间计时器是否正在运行。当前模板中，计时运行时直接完成会导出 `true`，先暂停再完成会导出 `false`；两种路径都可以生成合法的只读 shared。不得把任一值机械统一成另一值，也不得仅凭该字段判定作业错误、AI 生成或需要返修；详细判断读 [annotation-form-contract.md](references/annotation-form-contract.md)。
- 不伪造耗时，不为报价或通过率虚增时间。
- 轨迹不写内部提示语、绝对路径或无关工具日志。
- 报告、轨迹、Rubric问题说明、备注和总体理由使用自然、具体的专业中文，避免空泛解释、模板化排比、过度总结和其他明显AI腔。无问题且页面强制非空时，可重复使用页面认可的最短无内容说明；具体核验依据保存在单题证据中。中文与相邻英文或数字之间不留空格，例如写成`Seata故障`、`2025年`、`P99延迟`；代码、命令、路径、公式、日志原文及英文短语内部的必要空格保持不变。

### 6. 逐条审核 Rubric

先从源文件独立核验每条Rubric，再填写当前HTML要求的字段；已完成产物用于交叉检查，不能替代源文件推导。页面字段包括：

- 数值/事实正确性；
- 源文件支撑性；
- 主观性/争议性；
- 质量评分；
- 问题与修改建议；
- 其他备注。

源文件支撑不等于 Rubric 自身说得通。方向性概括必须扫描反例，不得只验证第一个支持样本。Rubric 判定基准是“AI 能否仅由工作区源文件得出该条结果”，不得拿结果文件跑 Rubric 判定；AI 判定与源文件矛盾时回源核实，不照抄。“主观/有争议”仅指不同专家会得出不同结论的情形，事实性缺失不算主观。

数值/事实正确性只评断言的事实真伪（源文件能否支撑该数值/事实），不评产物是否承载该内容；输出缺列、缺说明行等“未承载”问题属于结果文件侧修复项或判分口径问题，记录在问题与修改建议中，不据此把事实正确性判否。数值类条目必须逐条回源文件核对并保留路径与数值证据，不得以“同批次/同模式一致”推定通过。

单条Rubric按自身事实、源文件支撑、口径和客观判分条件独立评分，无缺陷时给5分。“自身矛盾”指本条内部矛盾；纯粹的跨Rubric冲突记录涉及编号、互斥条件和修改方向，影响题目质量与总体判定，不直接把本条打成1分。本条另有事实错误或源文件支撑问题时，仍须按其自身缺陷扣分。

问题建议和备注只写实际需要说明的事项；无问题时按当前页面的可空或非空约定填写，不为填满字段虚构问题。文件定位时保留实际相对路径，页面搜索可使用文件名后段；同名和多版本的勾选、标签及阅读记录按下述表单reference核对。

填写或验证 HTML 时，读 [annotation-form-contract.md](references/annotation-form-contract.md)。

### 7. 完成题目级评分与判定

- 可完成性：熟练本岗位从业者仅用工作区能否完成并被客观判分；所需信息齐全、口径明确、结论唯一时给5分，存在数据缺失或必要假设时按当前页面档位和实际影响扣分。
- 难度：以熟练本岗位从业者为对象，与原难度标签比较，按当前页面档位评价实际业务复杂度；简单题按实际情况评分，3分及以下填写具体原因。具体档位见[annotation-form-contract.md](references/annotation-form-contract.md)。
- 质量：按题目真实性、表述清晰度、考察价值及已核实的问题评分；无需要修正的问题时给5分，存在单条缺陷或跨Rubric冲突时按影响程度扣分。Rubric错得很多时总体判“修改后可用”且质量给2–3分；单条均为5分时仍须检查跨条冲突和题目级问题。
- 逐项判定任务真实性、文件真实性、信息与约束充足性、工作区可定位性、建议补充的 Rubric 和总体结论。
- 文件数量多、阅读量大、题目困难或题面范围较宽，本身不构成“建议废弃”的充分理由。只有熟练从业者无法稳定收敛材料范围、必要事实缺失、工作区无法定位、来源存在无法解决的实质冲突，或任务无法被客观判分时，才考虑废弃；范围虽宽但仍可通过模块、时间、材料类型或后发记录收敛时，优先评高难度或判“需修改后可用”。
- 导出前交叉检查目录树选择、轨迹、Rubric 和题目级判定；同一事实不得同时出现“存在/不存在”“支持/不支持”或其他互斥结论。

### 8. 生成 draft 和 shared 产物

- `annotate.html` 的表单填写、文件勾选、逐文件耗时、轨迹增删改、Rubric、题目级评分/判定、暂停/继续和导出，优先使用 Chrome DevTools MCP 集成（`mcp__chrome_devtools`）操作真实页面：先确认目标标签页并取最新快照，优先用 `fill_form`、`click`、`fill` 等可见控件操作，再回读状态。集成不可用或无法可靠完成当前页面操作时，才使用下述 CDP 套件；必须操作原生应用时使用 Computer Use。`evaluate_script` 和 `Runtime.evaluate` 只读，不能借其写入页面状态；也不得用 Playwright、浏览器控制台、DOM 注入或其他代码执行通道写入状态。
- 源 `annotate.html` 和所有内联 JavaScript 始终不可修改。除当前工作区 `AGENTS.md` 明确记载且适用于本题的旧轨迹 ID 专项校正例外外，不得直接编辑 draft/shared HTML 或 `PRESET_STATE`，也不得用 Node.js、Python、正则替换、模板拼接或其他脚本生成、修补、补齐或重排表单状态。专项校正仅限有真实事件时间证据的错误 ID，不得改变任何其他状态。计时、`validate()`、`collectCurrentState()`、`doExport()`、暂存、完成、只读模式和事件监听代码始终是不可变模板证据。
- 正常导出顺序为：在浏览器中完成全部字段并触发当前页面原生校验；工作结束时若按钮显示“暂停”则点击暂停，若已显示“继续”则保持暂停；点击“暂存”下载可继续编辑的 draft；随后点击“任务完成”下载只读 shared。不得把“暂存”当成“暂停”，不得绕过页面按钮自行生成下载文件。
- 导出后重新打开 draft/shared，回读计时、文件选择、轨迹、全部 Rubric、题目级评分、题目级判定和总体理由。draft 必须可编辑，shared 必须只读且重新打开后计时不增长；两份状态除页面原生导出差异外必须一致。
- 上传前必须提取源 `annotate.html` 与浏览器原生导出的 draft/shared 的全部内联脚本，将 `PRESET_STATE` 归一为空对象后逐字节比较并核对 SHA-256；同时比对 `script` 标签属性、源页面静态控件的事件处理器和 draft/shared 状态。任一未经解释的差异都阻断交付，不能拿“页面还能打开”代替完整性证明。
- 上传前从本题真实作业记录确定起止毫秒时间，运行 `node <本Skill目录>/scripts/validate_annotation_html_integrity.mjs --source <原始annotate.html> --draft <draft.html> --shared <shared.html> --time-start-ms <起始毫秒> --time-end-ms <结束毫秒>`。脚本核验 ID 归属、状态一致性和导出计时差；原生两次导出之间最多允许60秒的计时差。超出时从可信可编辑页面重新导出最终一对文件。其他校验失败也须回页面修正并重新导出；仅旧 ID 问题可在上述专项例外适用时按项目合同校正。校验脚本只读，不修改、重建或覆盖 HTML。
- Chrome 集成无法可靠操作当前页面时，可复用 `scripts/cdp/` 零依赖套件（`Runtime.evaluate` 仅限只读，写入只走可信 Input 事件）；用法与环境准备见 [scripts/cdp/README.md](scripts/cdp/README.md)。任务特定的文件清单、耗时映射和填写计划放单题 `build/`，不改套件脚本。
- shared HTML 文件名为 `<TaskID>_annotate_shared.html`，使用当前题核对过的完整 Task ID。例如 `题目016_v46_backend_bulk_007_annotate_shared.html`。
- 结果文件服从当前任务原文的文件名、格式、路径和内容要求。任务结果文件为 `1–2` 个时按原文件分别交付；超过 `2` 个，即 `3` 个及以上时，只把题面要求的结果文件打包为一个 ZIP 上传，命名为 `<TaskID>_结果.zip`，例如 `题目068_V3_0362_结果.zip`。结果 ZIP 不包含 draft、shared、证据、脚本、日志或中间文件；上传前核对 ZIP 文件清单、CRC 和解包后哈希。
- 任务要求的原始产物、上传重命名副本、draft HTML 和 shared HTML 是不同产物，分别保留。
- 对外交付件不得暴露其生成过程：不得出现模型或工具名称、生成提示语、本机绝对路径、脚本/证据目录、调试日志、源码映射、内部工作备注、`generated by` 类署名，或作者、最后修改者、批注、修订记录、自定义属性中的生成工具信息。自然专业表达和中文-英文/数字边界格式也属于发布检查，不只检查正文结论。
- Office产物的创建时间和最后修改时间必须与单题证据中的真实首次生成、最终保存时间一致。预计完成日期、上传日期、当前检查时间和模板默认日期都不能替代真实文档时间；没有可靠证据时宁可保留字段缺失并说明，不能编造一个“看起来正常”的时间。旧版`.doc`等格式若属性流本身没有创建/修改字段，转换工具显示的`1601/2002`兼容占位不视为真实元数据，也不强行补写；作者、最后保存者和创建应用等身份字段继续保持为空。
- 只修正文档属性时必须证明正文没有被改动：DOCX至少比较正文XML和样式XML并重新渲染；旧版`.doc`至少做正文回读、关键内容检查和逐页渲染。元数据清理不能改变题面要求的格式、内容、表格或版式。
- 不把平台原始模板合同误判为生成痕迹。`annotate.html` 原本要求的任务 Prompt、`TASK_PROMPT`、任务配置、文件树和校验器字段必须保留；只清理本次制作过程额外写入的来源标记、注释和内部信息。若只读校验器对源模板已有的词语给出 `warnings`，逐项回源确认并在单题证据中说明；未解释的警告阻断交付。
- 生成过程、只读检查命令和本地回执只保存在单题 `evidence/`，不得混入原始期望输出、draft/shared HTML 或上传副本。清理生成痕迹不得删除业务证据、伪造来源、改变专业结论或掩盖真实冲突。
- 对外交付前按 [delivery-and-submit-boundary.md](references/delivery-and-submit-boundary.md) 执行状态与授权检查。

## 交付状态语义

- `SOURCE_READY`：来源和任务身份已固定，未开始产出。
- `LOCAL_TASK_COMPLETE`：期望输出物已在本地工作副本完成，Rubric/HTML 可能尚未完成。
- `DRAFT_READY`：draft HTML 已生成并通过本地基础检查。
- `SHARED_READY`：shared HTML 和所有本地交付件已通过发布检查，尚未上传。
- `UPLOADED`：文件已上传且完成远端回读，不等于最终提交。
- `SUBMITTED`：已获得明确的最终提交成功回执。

不得用“已完成”混淆上述状态。

## 维护边界

- 本 Skill 只保存跨任务稳定的决策逻辑和交付机制。
- live URL、当前群名、最近核实时间、项目特定授权和工具路由属于工作区 `AGENTS.md`。
- 单题 Prompt、Rubric、统计、模型结果、轨迹和回执属于单题材料目录。
- `scripts/cdp/` 是已由 v46 批次多题验证过的页面操作套件（原各任务 `build/` 脚本的收敛）；新模板 DOM 变化时先只读探测再改套件。未验证的新自动填表流程仍先留在单题 `build/`，多题复用后再合入。
