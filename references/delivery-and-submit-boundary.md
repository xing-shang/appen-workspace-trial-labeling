# 交付、回读与提交边界

## 何时读取

当任务接近本地完成、需要命名/封装产物、上传文件、写回在线表、点击提交或说明当前状态时，读本文件。

## 产物分层

不同产物不得相互覆盖或混用：

1. **源压缩包**：下载原件，保留原名、大小和 SHA-256，不在其中写入结果。
2. **解包源快照**：用于核对原始结构，默认不修改。
3. **单题工作副本**：真实执行任务的目录，期望输出物放在题面要求的相对位置。
4. **上传重命名副本**：按在线表或项目方要求命名，不替代工作副本中的原始期望输出物。
5. **结果 ZIP**：题面要求的结果文件超过 `2` 个时，将这些结果文件打包为 `<TaskID>_结果.zip`；不混入 HTML、证据或中间文件。
6. **draft HTML**：可继续返修，用于漏项和证据检查。
7. **shared HTML**：通过当前 HTML 校验器后生成的只读完成页。
8. **证据与回执**：检查命令、读回结果、哈希、上传响应和提交成功回执。

## 输出合同与结果目录

文件名、格式、相对路径和内容范围按以下顺序判断：

1. 当前任务 Prompt 或任务原文中的明确输出要求；
2. 当前任务包内针对输出文档的专项要求；
3. 页面或模板中的泛化“期望输出”和默认命名。

下位来源只能补充，不得覆盖上位来源的明确要求。不同来源发生会改变交付内容的实质冲突时，保留原文和适用位置，停止生成最终产物并刷新 live 规则或请求确认。

结果目录采用交付 allowlist：只保留题面明确要求的文件。临时文件、转换中间件、调试输出、扫描报告、证据日志和本地辅助脚本放在工作副本的证据/临时目录，不随结果文件上传。上传前按相对路径逐项核对 allowlist，避免文件冗余。

上传时按任务结果文件数量处理：结果文件为 `1–2` 个时分别上传原文件；结果文件为 `3` 个及以上时，只将结果文件打包为一个 ZIP，命名为 `<TaskID>_结果.zip`，例如 `题目068_V3_0362_结果.zip`。这里的数量只统计任务原文要求的结果文件，不统计 draft、shared、证据或上传回执。任务原文若明确要求其他封装方式，保留冲突并按当前规则优先级核实，不自行增加双份交付。

## 本地发布检查

进入 `SHARED_READY` 前必须确认：

- 任务身份、岗位、Prompt、工作区和期望输出一致；
- 源包未被覆盖，工作发生在独立副本；
- 对 `extracted/` 原始工作区与 `work/` 工作副本执行字节级差异检查或完整文件清单哈希比较，并把结果保存到 `evidence/`。允许的差异只能是题面明确要求、且源工作区中原本不存在的输出路径；任何既有文件被修改、删除、重命名、移动或覆盖都必须阻断交付；
- 题面要求的文件存在于正确相对路径；
- 结果目录与交付 allowlist 一致，没有临时或冗余文件；
- 结果文件数量与上传方式一致：`1–2` 个分别上传，`3` 个及以上使用 `<TaskID>_结果.zip`；ZIP 已通过文件清单、CRC、解包和逐文件哈希检查，且不包含 draft/shared/evidence；
- 上传副本与原始产物内容一致，仅命名不同；
- 实际使用文件、页面勾选文件和轨迹提及文件相互覆盖，所有勾选文件有真实耗时；
- 整体 Session 为 `01:00:00–02:00:00`，来自真实浏览器页面计时，不是脚本或 HTML 状态改写结果；总阅读时长按文件复杂度填写，与整体 Session 的差额为约 `50` 分钟，正常落在 `45–55` 分钟；
- 所有 Rubric 和条件必填字段已完成；
- 题目级评分、判定、总体理由和目录树勾选完整；
- 同名文件、文件数量、真实性等事实在轨迹、Rubric、题目级判定和总体理由中没有互斥结论；
- draft 和 shared HTML 重新打开后状态不丢失，shared 为只读完成状态；
- draft/shared 必须优先通过 Chrome DevTools MCP 集成操作真实页面并点击原生“暂存”“任务完成”按钮；集成不可用时才使用 `scripts/cdp/` 或 Computer Use。不得由 Playwright、浏览器控制台、`evaluate_script`、`Runtime.evaluate`、DOM 注入、Node.js、Python、正则或模板代码直接生成、修补或重排常规表单状态；工作区 `AGENTS.md` 明确记载的旧轨迹 ID 专项校正仅限其适用范围；
- shared 重新打开后计时不再增长；`_timer.running` 只表示导出瞬间是否正在计时，可以因“运行中完成”或“暂停后完成”分别为 `true` 或 `false`，不得将任一值单独作为交付失败或返修依据；
- draft/shared 的轨迹 ID 符合当前页面原生生成规则，属于当前题真实作业起止时间，步骤顺序一致且两份文件相互对应；没有语义化 ID、统一纠正时刻、整秒等距序列、未来时间或其他任务时间；
- 对当前任务原始 `annotate.html` 和待上传 draft/shared 提取全部内联 JavaScript，将 `PRESET_STATE` 归一为空对象后逐字节比较；脚本长度、内容和 SHA-256 必须一致。`script` 标签属性、源页面静态控件的事件处理器也应保持一致。计时、校验、导出、暂存、完成、只读模式或事件监听代码任一变化均阻断上传；
- 运行 `node <本Skill目录>/scripts/validate_annotation_html_integrity.mjs --source <原始annotate.html> --draft <draft.html> --shared <shared.html> --time-start-ms <起始毫秒> --time-end-ms <结束毫秒>` 做同一门禁；只有返回 `ok: true` 且 `warnings` 逐项回源解释后才继续上传。该脚本只读检查脚本、静态页面执行入口、轨迹 ID、draft/shared 状态与导出计时差，不能修改、重建或覆盖 HTML；脚本检查不能取代真实页面 `validate()` 和重新打开后的回读。失败时回浏览器修正并重新按钮导出，适用旧 ID 专项例外时按工作区合同处理；
- 产物不包含本地绝对路径、群名、内部 URL、成员信息、内部提示语、凭据或无证据推测；
- 对所有待上传文件执行生成痕迹扫描：正文、隐藏文本、HTML 注释、脚本常量、文件属性和 OOXML 内部部件中不得出现模型/工具名、生成提示语、`generated by` 类署名、本机路径、工作副本路径、证据目录、辅助脚本名、调试日志、源码映射、浏览器侧栏/批注注入节点或内部工作备注。业务材料原文中的 `localhost`、AI目录名或工具术语只能在有当前源文件支撑时保留，不能按字符串机械删除；
- 检查 DOCX/PPTX/XLSX 的作者、最后修改者、批注、修订记录和自定义属性。存在制作工具或内部身份残留时先清理再重新渲染；不得用清理元数据替代内容核验；
- Office元数据只能通过真实可用的Office工作流或文档规范允许的属性清理处理。没有对应应用时，不手改OOXML去冒充Microsoft Office、伪造创建应用或虚构作者；无法真实清理时保留原件并报告，不以隐藏来源为由破坏内容或伪造来源。
- 检查Office内部创建/修改时间是否有单题证据支撑。创建时间对应首次生成，修改时间对应最终内容保存；不得写成预计完成日期、上传时间或检查时间。时间使用UTC存储时必须正确换算本地时区，并在证据中同时保留本地值和内部UTC值；
- 旧版`.doc`若实际属性流中没有创建时间、最后保存时间、作者或创建应用字段，不因`textutil`等读取器显示`1601/2002`兼容占位而强行补写。先用结构化OLE元数据读取确认字段是否真实存在；缺失字段保持缺失，禁止伪造；
- 元数据返修后执行内容不变检查：DOCX比较`word/document.xml`、`word/styles.xml`并重新渲染全部页面；旧版`.doc`重新回读正文、核对关键章节/数值/表格并逐页渲染。任何正文或版式意外变化都必须阻断上传；
- 平台模板原生字段不属于生成痕迹。不得删除 `annotate.html` 合同要求的任务 Prompt、`TASK_PROMPT`、任务配置、文件树或校验器；只清理制作过程额外写入的信息；
- 对外正文使用自然、具体、符合岗位习惯的表达，避免连续模板句、机械排比和明显 AI 腔；中文与相邻英文/数字之间不留多余空格，但代码、命令、路径、公式、日志原文和英文短语内部必要空格保持不变；
- 生成与审计过程只进入 `evidence/`，不得随原始期望输出、draft/shared HTML 或上传副本交付；
- 报告的本地状态词与证据一致。

## 外部操作授权

以下授权互不包含：

| 用户指令 | 允许动作 | 不包含 |
| --- | --- | --- |
| `开始试标` / `做完` / `做成可交付` | 本地任务产物、Rubric、draft/shared HTML 生成与验证 | 上传、飞书回表、最终提交 |
| `开始做正式题` / `做这道题` | 对当前已精确分配或领取的任务进行本地作业 | 领取其他题、修改在线状态、上传、提交 |
| `上传文件` | 上传当前指定任务的明确文件并回读 | 写表、提交、处理下一题 |
| `回填试标表` | 写入当前指定行/任务字段并回读 | 最终提交、上传未授权文件 |
| `提交这道试标` | 核对当前任务身份与完整字段后提交该任务 | 自动领取、提交下一题或批量提交 |

用户说“按你说的来”只授权已说明方案内的本地实施；除非方案已明确包含具体外部动作和对象，不得将其扩展为上传或最终提交授权。

## 回读和回执

- 上传返回成功后，回读远端文件名、大小或可用哈希，确认是当前任务文件。
- 覆盖HTML后重新下载远端源文件，与本地最终版逐字节比较；再次执行脚本归一对比和直接标记扫描，不能只相信上传响应或本地检查。
- 在线表写入返回成功后，回读精确行和所有目标列，确认值、公式、链接和任务身份。
- 页面显示已保存不等于已提交。
- 只有明确的最终成功回执才能记录 `SUBMITTED`。未获得回执时报告真实停留状态。

## 失败停止条件

遇到以下任一情况时停止外部动作，保留本地证据并报告：

- 当前任务 ID、页面行或上传目标不唯一；
- live 规则与当前产物发生会改变结论的冲突；
- 上传或写回响应无法确认实际生效；
- 页面出现未在授权范围内的“提交并加载下一条”等复合动作；
- 高风险写操作的目标或影响范围不明确。
